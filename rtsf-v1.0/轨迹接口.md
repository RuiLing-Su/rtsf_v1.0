# 轨迹接口

本文定义实际运行轨迹的采样、批次、补传和完整性判断，供云端实时展示与落库。

## 轨迹上报：trajectory.batch

**Topic：** `rtsf/v1/{robot_id}/trajectory`，设备→云，QoS 1，retain=false。

RUNNING 和 PAUSED 期间按 5 Hz 调度采样，每约 2 秒组批；任务终态发送最终批次。完整报文：[普通批次](examples/trajectory_batch.json)、[最终批次](examples/trajectory_final.json)。

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| task_id | string | 是 | 所属任务 |
| map_id | string | 是 | 任务地图版本 |
| base_frame_id | string | 是 | 与该 map_id 元数据一致的位姿参考点 |
| path_id | string | 是 | 所属路径 |
| path_version | integer，≥1 | 是 | 当前路径版本；单批不混合版本 |
| batch_seq | integer，≥0 | 是 | 同任务从 0 连续递增，路径更新不重置 |
| final | boolean | 是 | true 为最终批次 |
| samples | array | 是 | 按 t 严格递增；仅最终批次可为空 |

### 采样点

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| t | int64 | 是 | 位姿采样时间，UTC 毫秒 |
| x、y、yaw | number | 是 | base_frame_id 在 map 中的位姿，m/rad |
| speed_mps | number，≥0 | 否 | 速度大小 |
| vx、vy | number | 否 | map 中的速度分量，m/s |
| wz | number | 否 | 角速度，rad/s |
| wp_seq | integer，≥0 | 否 | 当前前往航点 |
| loc_quality | string | 否 | GOOD、DEGRADED、LOST |

定位无效、过旧或时间重复时不生成伪样本，每批不保证恰有 10 点。缺省速度表示未知，不能按零展示。任务航点和实际轨迹分别展示，不用航点连线冒充轨迹。

## 缓存与补传

设备端持久保存待发送批次，断网恢复后按原编号补传。重传保留原信封、批次内容和采样时间，不重新编号，也不把历史数据合并为大包。

每条报文仍受 64 KiB 限制。待发送缓存不足时拒绝新任务；运行中无法继续可靠记录时，以 INTERNAL_ERROR 失败并请求停止，不静默删除未发送批次。

任务终态后不生成新批次，允许旧批次重传。未开始执行即取消的任务也发送 final=true，可为空数组，batch_seq=0。

## 云端处理

| 检查 | 规则 |
|---|---|
| 批次去重 | `(robot_id,task_id,batch_seq)` |
| 样本去重 | `(robot_id,task_id,t)` |
| 乱序 | 按 batch_seq 与采样时间重排 |
| 内容冲突 | 同键内容不同则记录一致性错误，不覆盖历史 |
| 完整性 | 从 0 到 final 批次之间所有批次均已落库 |

收到任务 COMPLETED 或 final=true 都不能单独认定轨迹完整。存在缺口时保持“不完整”，补齐后再更新。

本接口不提供批次业务确认或按编号补拉。PUBACK 后仍可能发生云端消费或落库失败，不能把 QoS 1 理解为数据库无损保证。云端需持续订阅、可靠消费并监测缺口。
