# 通信协议

本文定义所有接口共用的 Topic、消息信封、重试与排序规则。

## Topic

公共前缀为 `rtsf/v1/{robot_id}/`，全部 QoS 1。

| 后缀 | 方向 | method | Retain |
|---|---|---|---|
| services | 云→设备 | task.path.set、task.start、task.pause、task.resume、task.cancel | false |
| services_reply | 设备→云 | 与原服务请求相同 | false |
| properties/device | 设备→云 | device.state | true |
| properties/map | 设备→云 | map.info | true |
| properties/task | 设备→云 | task.state | true |
| events | 设备→云 | task.state_changed、device.fault | false |
| trajectory | 设备→云 | trajectory.batch | false |

Topic 中的 robot_id 必须与报文一致。属性保留最新快照；事件和轨迹不是 retained 数据。

## 公共字段

业务参数全部放在 data 内。各接口的参数表均描述 data，不重复列出公共字段。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| schema_version | string | 是 | 固定为 1.0 |
| message_id | UUID string | 是 | 消息唯一标识；重传保持不变 |
| robot_id | string | 是 | 设备标识 |
| timestamp | int64 | 是 | 消息生成时间，UTC Unix 毫秒 |
| method | string | 是 | 接口标识 |
| request_id | UUID string | 仅服务回复 | 原请求的 message_id |
| data | object | 是 | 接口参数或上报内容 |

```json
{
  "schema_version": "1.0",
  "message_id": "00000000-0000-4000-8000-000000000002",
  "robot_id": "go2-01",
  "timestamp": 1700000002000,
  "method": "task.start",
  "data": {"task_id": "task-001"}
}
```

设备、任务、路径、地图和故障 ID 长度为 1–64，允许字母、数字及 `._:-`。method 使用小写点分名称，最长 64 字符。时间为非负 int64；位置 m，角度 rad，速度 m/s，角速度 rad/s。

报文采用 JSON/UTF-8，完整原文含空白与扩展字段不超过 65536 字节。拒绝重复键、NaN、Infinity 和数值溢出；不分片、不截断。未知扩展字段不影响业务处理，已定义但不支持的功能明确拒绝。

## 服务回复与重试

设备端对可关联的服务请求在 3 秒内回复。回复使用独立 message_id，通过 request_id 引用请求。ACCEPTED 表示受理，执行结果通过任务属性和事件上报。

云端每轮等待 3 秒，无回复则重传原消息，最多重传 3 次，即最多发送 4 次。收到接受或拒绝均停止重试。最终仍无回复时，记录受理结果未知，不能认定设备未执行。

设备端按 `(robot_id,message_id)` 持久去重。相同请求重发原回复，不重复执行；同 ID 不同内容返回 MESSAGE_ID_CONFLICT，保留原记录。幂等记录至少保留 7 天，活动任务相关记录在终态前不清理。云端不复用 task_id。

无法提取合法关联字段、method 格式非法或身份不匹配的输入丢弃并记诊断，不伪造回复。超限报文不保证收到业务回复。

## 排序与结果判定

| 标识 | 用途 |
|---|---|
| message_id / request_id | 消息去重、请求回复关联 |
| task_id | 关联同一任务的服务、状态、事件和轨迹 |
| path_id / path.version | 标识任务路径及其更新版本 |
| revision | 同一任务属性的修订号，防止乱序回退 |
| batch_seq | 轨迹批次编号，用于去重与缺口检查 |

任务属性内容变化时 revision 递增并持久化；内容不变的心跳不递增。状态事件与对应属性使用相同 revision。云端只用更高 revision 更新同一任务快照，不比较不同任务的 revision。

PUBACK 只确认当前 MQTT 链路，服务回复只确认受理，任务终态只确认执行结果。轨迹是否完整，需另行核对全部批次是否落库。
