# 接入指南

本文说明 MQTT 接入配置、权限和首次对接步骤。

## 连接配置

| 配置项 | 要求 |
|---|---|
| Broker | 云端提供主机名、证书信任链及账号 |
| 传输 | MQTT 3.1.1，TLS 8883，校验服务端证书 |
| robot_id | 唯一设备标识；示例 go2-01 |
| 设备 client_id | 同一设备保持固定；示例 rtsf-go2-01 |
| 平台 client_id | 与设备端不同，每个并行连接唯一 |
| 会话 | clean_session=true，keepalive=10 秒 |
| QoS | 全部消息为 1 |
| 大小限制 | JSON 原文最大 65536 字节；Broker 最大 MQTT 报文至少 131072 字节 |
| 重连 | 依次等待 1、2、4、8、16、30 秒，之后保持 30 秒；连接成功后重置 |
| 时钟 | 双方同步时钟，使用 UTC Unix 毫秒 |

设备账号只访问绑定设备；平台账号只访问授权设备。口令和密钥通过私密渠道交付。

## Topic 权限

以下为 `rtsf/v1/{robot_id}/` 后缀。除授权方向外均拒绝。

| Topic 后缀 | 设备账号 | 平台账号 |
|---|---|---|
| services | 订阅 | 发布 |
| services_reply | 发布 | 订阅 |
| properties/device | 发布 | 订阅 |
| properties/map | 发布 | 订阅 |
| properties/task | 发布 | 订阅 |
| events | 发布 | 订阅 |
| trajectory | 发布 | 订阅 |

服务请求禁止 retained，接入前清除 services 的历史 retained 消息。鉴权和 ACL 需分别验证；不能只凭连接成功或 PUBACK 判断授权生效。

## 首次接入

1. 确认 Broker、证书、账号、设备标识和文件服务配置；验证合法访问成功、越权访问失败。
2. 云端订阅六个上行 Topic，设备端订阅 services 并注册离线遗嘱。
3. 设备端上线后依次发布设备、地图和最新任务属性（如有），再补传待发送事件与轨迹。
4. 云端确认心跳有效，下载地图，校验 ZIP 的 SHA256、尺寸、分辨率与原点。
5. 云端调用 task.path.set；收到受理回复及 ACCEPTED 状态后调用 task.start，持续接收任务状态和轨迹。

先在不驱动实际运动的环境完成报文与流程联调，再验收真实定位、运动和停车。网络接入成功不等于设备具备运动条件。

## 文件服务配置

文件服务方提供上传或发布方式、鉴权、大小限制、成功响应和下载地址。设备端确认文件可下载后，在 map.info 中发布 URL 与 SHA256。RTSF 不规定文件服务的上传 API。

## 上线与离线

在线时每 5 秒发布 device.state。云端收到 online=false，或超过 15 秒未收到有效在线心跳，即判定离线；超时按云端单调时钟计算。首次订阅收到的过旧 retained 快照不能作为在线依据。

设备异常断开时由 Broker 发布遗嘱。遗嘱携带完整信封，data.source=LWT；其 timestamp 是注册遗嘱的准备时刻，云端按收到遗嘱的时刻判定离线。正常退出使用 source=SHUTDOWN 上报离线并确认传输，再断开连接。

clean_session=true 不保留离线下行队列。MQTT 重连不自动启动或恢复任务；设备进程重启不自动恢复运动。
