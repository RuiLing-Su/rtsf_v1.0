# 联调指南

本文说明如何校验交付包、检查报文，并验收云端与设备端的交互。

## 报文校验

需要 Python 3.8 或更高版本。在本目录执行：

```bash
python3 -m pip install jsonschema==4.21.1 jsonschema-specifications==2023.12.1 \
  referencing==0.35.1 rpds-py==0.18.1 attrs==24.2.0
python3 -B validate.py
python3 -B validate.py --profile --topic rtsf/v1/go2-01/services examples/task_path_set.json
sha256sum -c SHA256SUMS
```

不带文件时运行自检；带文件时校验指定 JSON。--profile 额外检查航点能力，--topic 检查完整 Topic 与 method、robot_id 和消息方向是否匹配。退出码 0 表示通过，1 表示失败。

`schemas/rtsf.json` 是 JSON Schema Draft 2020-12 入口。全部引用本地解析，无需访问 Schema ID 域名。校验器检查严格 JSON、字段、语义、能力和路由；不检查实际有效期、地图可达性或设备状态。

样例分别说明报文结构，不应原样串联发送。实际下发时使用当前时间、新 message_id、新 task_id、有效 map_id 和未来 expire_at，不直接发送样例中的历史时间。files.example.com 是占位下载地址。

## 场景验收

先完成不驱动实际运动的流程验收，再测试真实定位、绕障和停稳。模拟结果不能替代真机结果。

| 场景 | 通过条件 |
|---|---|
| 连接与权限 | TLS 和账号正确可连接；错误证书、账号及越权访问失败 |
| 上下线 | 每 5 秒心跳；正常退出与遗嘱可判离线；旧 retained 不误判在线 |
| 地图 | 文件可下载，整包 SHA256、尺寸、分辨率、原点与参考点一致 |
| 正常任务 | 路径受理不自动运动；START 后运行，最终 COMPLETED 及 final 批次 |
| 暂停与恢复 | 受理与停稳分开；停稳后 PAUSED，RESUME 重新校验并恢复 |
| 取消 | ACCEPTED、RUNNING、PAUSED 下均可取消；停稳后 CANCELED |
| 路径更新 | 旧版本拒绝、同版本同内容不重置、冲突拒绝；无效更新不影响旧任务 |
| 非法请求 | 结构、超限、过期、地图、能力、航点和就绪错误分类正确 |
| 命令状态 | 未知任务、非法状态、处理中冲突操作不执行 |
| 幂等与回复 | 重传不重复动作；同 ID 不同内容拒绝；迟到回复仍正确关联 |
| 属性与事件 | 状态变化事件与属性 revision 一致，心跳不生成变化事件，乱序不回退 |
| 故障 | 急停、失定位、受阻和低电量正确上报；解除不自动恢复任务 |
| 轨迹 | 采样坐标正确；批次连续、可去重；断网恢复原样补传，缺口标记不完整 |
| 重连与重启 | 重连不自动操作；进程重启不自动运动，原任务失败并结束轨迹 |

断网补传应分别测试设备端链路中断与云端消费故障，两者的可靠性边界不同。真实停车需观察设备反馈，不能以受理回复、离线或 FAILED 代替。

每项记录环境、设备标识、任务与消息 ID、预期、实测及日志位置。报文自检和业务验收分别记录，不以自检结果代替场景通过。
